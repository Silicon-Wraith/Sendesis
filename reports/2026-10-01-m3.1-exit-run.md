## Known issue: Codex stream stalls

Five codex-gpt cases timed out at 300 s: cve-0001, cve-0005, cve-0006, cve-0017, cve-0019.

What the Codex session files (`~/.codex/sessions/**/rollout-*.jsonl`) and Codex's log (`~/.codex/logs_2.sqlite`, read only) show for all five:

1. Codex read files with shell commands, as in the cases that passed.
2. It finished reasoning and opened the final answer: the log records an output item of type `message` starting.
3. Then nothing arrived for 218 to 271 s: no text, no token counts, no error, no warning. Sendesis's 300 s limit aborted the turn (`turn_aborted`, reason `interrupted`).

In the 25 cases that passed, the longest silence in any session was 16 s, and the final answer streamed in about 8 to 18 s.

A diagnostic rerun of the five cases through the same seat path, with every app-server message timestamped and a 900 s ceiling, passed all five (38 to 150 s each). Answers streamed in 8.0 to 18.3 s, the longest silence was 13.6 s, and no error, reroute or retry events appeared.

Conclusion: the stall is intermittent and not caused by the case content. The most likely cause is the provider's response stream going silent mid-answer. That was not caught in the act, so a runaway answer that was never written out cannot be fully ruled out. Codex's own stream idle timeout (`stream_idle_timeout_ms`, default 300,000 ms) equals Sendesis's per-call limit, so Codex never got the chance to reconnect before the turn was aborted.

A concurrent Codex session in another project (21:26 to 21:33 UTC) overlapped one stall (cve-0006) but none of the other four.

### Follow-ups (not in M3.1)

- **Idle limit:** add an idle limit alongside the wall-clock limit, ending a call that has sent no event for about 60 s. This belongs in agno-cli-models, which sees the events. It could also set Codex's `stream_idle_timeout_ms` when it starts `codex app-server` so Codex reconnects by itself.
- **Stalls in Sendesis:** decide how qualification treats a stall. It is an infrastructure failure, not a model miss. Options are one retry, like the retry on invalid output, with the stall recorded on the receipt either way. This changes receipt rules, so it needs a design decision first.
- **Isolation leak:** every Codex call received the user's global skills block and a multi-agent developer prompt. Its feature flags include `Collab`, `SleepTool` and `CodexHooks`. agno-cli-models' isolation does not remove these. This belongs in its backlog.
