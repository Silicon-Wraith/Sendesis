# M3.2: Router and failover

Status: written for review, not yet approved.

Parent spec: `docs/specs/2026-10-01-sendesis-m3-design.md`.
- **Section 1.1, M3.2 row:** "Cut one provider mid-stage: the stage resets and finishes on a qualified profile, or refuses naming what is missing."
- **Section 5:** router and failover rules.

This document makes those rules concrete for code that exists today. It changes none of them.

## Problem

The router is the only component that chooses models (M3 spec, section 5). Until it exists, nothing can run a stage. The compiler that runs whole workflows arrives in M3.3 and needs routing and failover underneath it.

Two facts shape M3.2:

1. **No stage executor exists yet.** `run_role` runs one seat, and `workflow.py` loads stages, but nothing runs a stage's seats. The parent spec's exit criterion says "mid-stage".
2. **No profile qualifies for any role today.** The only role with a suite is the Security Reviewer, and both of its receipts read UNKNOWN: "suite has 30 cases, role requires at least 100". Under section 5 a real Security Reviewer stage must refuse. Also, `roles/` holds no provisional reviewer.

Seats with edit or shell tools raise `SandboxUnavailable` until M3.3, so in M3.2 only reviewer seats can run.

## Design

### 1. Components

**`src/sendesis/router.py`: choosing profiles.** These are pure functions that call no model.

- `candidates(role, profiles, root, now, excluded) -> list[Candidate]`:
  - walks `role.failover_order`;
  - gives each profile one verdict, acceptable, provisional or rejected, with a reason (section 2).
- `assign(stage, roles, candidates, fixed, excluded) -> Assignment | Refusal`:
  - fills the stage's seats in workflow order, taking each role's profiles in `failover_order`;
  - backtracks so that `distinct_families` holds;
  - returns one profile per seat, or a refusal (section 2).

**`src/sendesis/failover.py`: running one seat until it succeeds or nothing is left.**

- `run_seat_with_failover(...) -> SeatRun` does four things:
  - runs the seat through `run_role`;
  - on a failover trigger, records the attempt and resets the seat's work (section 3);
  - excludes the failed profile;
  - asks `assign` again for the whole stage, with finished seats fixed, and reruns the seat from its original input.
- It returns the seat's final result. When no assignment is left, it returns a refusal instead.

**`src/sendesis/stage.py`: running one stage.** It takes a loaded workflow stage and an input message, then:

1. checks the tree is clean;
2. routes every seat before any model call;
3. runs the seats one after another through the failover loop;
4. labels reviewer seats A, B and so on;
5. returns a `StageResult`:
   - each seat's final output;
   - every attempt with its reason;
   - the warnings;
   - a status of `completed`, `refused` or `stopped`, with a refusal or stop reason.

There is no adjudication, evidence pack or gate. Those belong to M3.3, which builds the compiler on `stage.py`.

**CLI: `sendesis stage <workflow> <stage-id> --diff <file> [--context <dir>]`.**
- It builds the reviewer message the way qualification does (`build_message`) and runs the stage.
- It prints the assignment, the attempts, the outcome and, at the end, the label-to-profile mapping.
- It writes the record (section 3).

M3.3 either keeps it as a debugging command or removes it.

Failover lives in Sendesis, wrapped around `run_role`, not in Agno. Agno's own retries know nothing about receipts, families, resets or the rate-limit skip list, so they stay off: `Agent.retries` defaults to 0, and seats keep that default.

### 2. Routing rules

**Candidates.** For each role, every profile in `role.failover_order` gets one verdict:

| Verdict | When |
|---|---|
| acceptable | The profile is enabled. Also, `receipts.effective_status` of the profile's latest receipt for this role reads QUALIFIED: unexpired, and nothing has drifted. |
| provisional | The role has no `qualification` block, and the profile is enabled with a family other than the placeholder `set-me`. It is accepted with the warning "`<role>` is provisional: no suite, profile `<profile>` not qualified". |
| rejected | Anything else. The reason recorded is the first that applies:<br>- profile file missing or invalid;<br>- disabled;<br>- no receipt;<br>- the receipt's effective status and reason (for example "UNKNOWN: suite has 30 cases, role requires at least 100", or "void: model class configuration changed");<br>- sandbox unavailable for the role's tools;<br>- rate-limited earlier in this run;<br>- failed this seat (`<outcome>`). |

Rejections are kept, so that every refusal can say why each profile was turned down.

**Assignment.** A stage's seats each have a role, a `count` and a `distinct_families` value.
- Seats are filled in workflow order. Within a seat, profiles are tried in the role's `failover_order`, and the first complete assignment found wins. The result is deterministic.
- `distinct_families: N` requires the `count` seats of a role to cover at least N families.
- With `N = 1`, one profile may fill several seats of the same role (N samples of one model).
- One profile may serve seats of different roles in the same stage.
- The search backtracks. If the first choice for an earlier seat leaves a later seat with no way to meet its family rule, the next choice is tried. Plain recursion suffices: a few profiles across a few seats.
- The inner loop's other-family checker rule is M3.4 and is not built here.

**Refusal** comes before any model call, or after a failover leaves no assignment. It names the stage, the role, the families needed and the families acceptable, and lists every rejected profile with its reason:

```
refused: stage review: security-reviewer needs 2 families, 1 acceptable (anthropic: claude-opus)
  rejected: codex-gpt: receipt UNKNOWN: suite has 30 cases, role requires at least 100
  rejected: ollama-local: disabled
```

**Reassignment after a failover.**
1. Finished seats keep their profile.
2. The failed seat may not reuse the profile that failed it, whatever the trigger.
3. A rate-limited profile is excluded from every seat for the rest of the run. A profile that stalled, timed out, errored or stayed invalid is excluded only for that seat.
4. `assign` runs again for the unfinished seats with those exclusions. It re-checks `distinct_families` across the whole stage, finished seats included.
5. If no assignment is left, the stage refuses.

### 3. Failover, resets and the record

**Triggers.** These follow the seat's final `Outcome`:

| Outcome | Same-profile retry first | Then |
|---|---|---|
| INVALID | one retry | fail over if still invalid |
| RATE_LIMIT | no | fail over; skip the profile for the rest of the run |
| TIMEOUT, STALL, ERROR | no | fail over; exclude the profile for this seat only |

STALL gets no same-profile retry in runs. Decision `stall-retry-once` gives that retry to qualification only; in runs, failover replaces it.

An exception that is not a typed outcome, meaning a bug in Sendesis, stops the stage with status `stopped` and is recorded. It is never failed over.

A budget overrun is not a failover trigger. Token budgets arrive in M3.3.

**Resets.**
- The stage starts only on a clean tree (`git status --porcelain` empty, ignoring git-ignored files). Otherwise it refuses with "dirty tree: commit or stash first". Sendesis never commits or stashes the operator's changes.
- At the start of every seat, the stage records `HEAD` and the set of untracked, non-ignored files.
- **Worker seat, on failover:**
  - run `git reset --hard <seat start>`;
  - delete the untracked files that were not in the start snapshot;
  - leave ignored files alone.
  - Workers cannot run until M3.3, so M3.2 tests this against a temporary git repository.
- **Reviewer seat:** after every attempt, the stage checks that `HEAD` and the working tree are unchanged. If a reviewer changed anything, the stage stops with "reviewer seat changed the tree" and is never failed over. This is a check on top of the read-only sandboxes.
- The next profile gets exactly the same input message.

**The record.** It lives in `.sendesis/runs/<run-id>/`, which is git-ignored. The run id is a UTC timestamp.

- `stage.json` holds:
  - the run id, workflow id and sha256, stage id, and start and end times;
  - the input's sha256;
  - `status` (`completed`, `refused` or `stopped`), with `refusal` or `stop_reason` when set;
  - `warnings`;
  - `initial_assignment` (label to profile);
  - `attempts`, in order: label, role, profile, family, outcome, reason, the `stall` block when present, wall time and tokens;
  - `seats`: per label, the final profile, the outcome and the path to the raw output.
- `seat-<label>.json` holds each seat's final output.

M3.3's run record and Agno session store take over from this file.

**Blinding.** Reviewer seats are labelled A, B and so on in the order they run. Profile names appear in `stage.json` and at the end of the CLI output. They never appear in any input a seat receives.

### 4. Testing and the exit

**Unit tier.** This is the default run, using the scripted fake model and scripted seat functions. It uses a fixture workflow; M3.2 ships no real workflow file.
- **`candidates`:**
  - every verdict and every rejection reason;
  - one test on the real repository's receipts, where a Security Reviewer stage refuses and names "receipt UNKNOWN: suite has 30 cases, role requires at least 100" for each profile.
- **`assign`:**
  - first fit;
  - a case that needs backtracking;
  - one profile filling several seats when N is 1;
  - one profile serving two roles;
  - the exact refusal text.
- **Failover:**
  - INVALID is retried once on the same profile, then fails over;
  - RATE_LIMIT excludes the profile from later seats;
  - STALL and TIMEOUT exclude it for that seat only;
  - finished seats keep their profile;
  - families are re-checked across the whole stage;
  - running out of profiles ends in a refusal;
  - an untyped exception stops the stage.
- **Resets** (temporary git repository):
  - a worker reset restores the start commit, removes new untracked files, and keeps ignored and pre-existing files;
  - a dirty tree is refused at stage start;
  - a reviewer that changes the tree stops the stage.
- **Record:** `stage.json` holds the attempts and the label-to-profile mapping, and no seat input contains a profile name.
- **CLI:** the output for completed, refused and stopped stages.

**Integration tier: the exit.** Marked `integration`, run in a temporary copy of the repository, with:
- a provisional reviewer role, `security-reviewer-provisional`, that reuses the Security Reviewer prompt and `finding.json` and has no `qualification` block;
- one stage, `review`, whose seat has `count: 2, distinct_families: 2`;
- `failover_order: [claude-opus, codex-gpt, ollama-local]`;
- `ollama-local` enabled on `hf.co/OBLITERATUS/Qwen3.8-27B-OBLITERATED:Q4_K_M` (family `qwen`);
- `idle_timeout_s: 15` on `claude-opus`.

Claude is cut by monkeypatching the seat builder so that `ClaudeCodeModel` gets `cli_path` set to a shim script. The shim answers `--version` with the pinned version and otherwise starts and stays silent.

1. **Failover completes.**
   - The initial assignment is A on claude-opus and B on codex-gpt.
   - A runs on the shim and stalls after 15 s with a real `CliStallError`.
   - claude-opus is excluded for A only. Reassigning the unfinished seats in first-fit order gives A codex-gpt and B claude-opus (anthropic plus openai, 2 families). A runs on codex-gpt.
   - B runs on the shim and stalls. claude-opus is now excluded for B too, so B gets ollama-local (qwen plus openai, 2 families) and finishes.
   - Expected:
     - the stage completes;
     - the attempts are, in order:
       - A stall on claude-opus;
       - A ok on codex-gpt;
       - B stall on claude-opus;
       - B ok on ollama-local;
     - `stage.json` is written;
     - the provisional warning is recorded.
   - This also shows that a stall excludes a profile for one seat only, not for the run.
   - Quota: one Codex call; the local call is free; two 15 s stalls.
2. **Refusal.**
   - The same stage, with `ollama-local` disabled.
   - A stalls on the shim and reruns on codex-gpt. B is assigned claude-opus and stalls.
   - Only codex-gpt is left for B, which gives 1 family where 2 are needed.
   - Expected: the stage refuses with "needs 2 families, 1 acceptable (openai: codex-gpt)". The rejections listed are:
     - "claude-opus: failed this seat (stall)";
     - "ollama-local: disabled".
   - Quota: one Codex call, for A.

**Exit evidence:** `reports/<date>-m3.2-exit-run.md` with:
- both runs;
- excerpts of both `stage.json` files;
- the refusal text.

**Docs:** the README CLI section gains `stage`, and the CLAUDE.md layout notes `.sendesis/runs/`.

## Design assertions

- The router MUST be the only code that chooses a profile for a seat.
- A profile MUST NOT be assigned to a seat of a role with a suite unless its receipt's effective status is QUALIFIED.
- A provisional assignment MUST record a warning.
- `distinct_families` MUST hold across a stage's seats of a role, at first assignment and after every failover.
- When no assignment exists, the stage MUST refuse before any further model call, and MUST name the role, families needed, families acceptable, and every rejected profile with its reason.
- A rate-limited profile MUST NOT be assigned again in the same run. A profile that stalled, timed out, errored or stayed invalid MUST NOT be assigned again to the same seat.
- A failed-over seat MUST rerun from its original input. A worker seat MUST first be reset to its starting commit, with only the untracked files it created removed.
- A stage MUST NOT start on a dirty tree. Sendesis MUST NOT commit or stash the operator's changes.
- A reviewer seat that changes the tree MUST stop the stage, and MUST NOT be failed over.
- An untyped exception MUST stop the stage and MUST NOT be failed over.
- No seat input may contain a profile name or a label-to-profile mapping.
- Agno's own retries MUST stay off for seats.

## Out of scope

- The compiler, evidence packs, adjudication, gates, commits and operator-edit detection during a stage (M3.3).
- Token budgets (M3.3).
- Worker seats with edit and shell, and the inner loop's other-family checker (M3.3 and M3.4).
- The gate-run rule that rate limits pause instead of failing over (decision 14, M3.6).
- Real provisional roles in `roles/` (M3.3, with their workflows).
- Real workflow files in `workflows/` (M3.3).

## Decisions to record on approval

In Sendesis's decision log, provenance human, actor John Sheppard:

1. `m3-2-router-library-and-stage-command`: M3.2 is a router and failover library plus a thin `sendesis stage` command. M3.3's compiler builds on `stage.py`.
2. `failover-in-sendesis-not-agno`: failover wraps `run_role` in Sendesis. Agno's retries stay off for seats.
3. `assignment-first-fit-with-backtracking`: assignment is first fit in `failover_order` with backtracking. With `distinct_families: 1`, one profile may fill several seats of a role.
4. `failover-exclusion-scope`: a profile that failed a seat is excluded for that seat only, except a rate limit, which excludes it for the rest of the run. In runs, STALL gets no same-profile retry.
5. `reviewer-tree-change-stops-stage`: a reviewer seat that changes the tree stops the stage and is never failed over.
6. `m3-2-exit-by-cli-shim`: the exit cuts a provider with a silent CLI shim set through the model class's own `cli_path`, on a provisional test role in a temporary copy of the repository.
